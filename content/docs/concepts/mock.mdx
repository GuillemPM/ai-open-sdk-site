`"AIOS Mock"` ships in **AI Open SDK** (core). It is an in-memory provider for text and image generation: no HTTP and no API keys.

Core and provider logic that you cover in CI should pass with Mock. Live API keys stay out of the pipeline.

## Why it matters

AI calls are side effects. With Mock you assert on prompts, structured output, and tool loops deterministically:

- Tests run without secrets or network
- Failures stay reproducible
- Provider outages do not block CI

## Setup

1. Depend on **AI Open SDK** (core).
2. Queue the next response (or error / tool call) on the factory before binding `Mock.Model(...)` or `Mock.ImageModel(...)`.
3. Call `"AIOS Client"` with the bound model.

<include lang="al" meta='title="GenerateText.al"'>samples/mock/GenerateText.al</include>

The queued response comes back verbatim, which is what makes assertions stable:

```text
Hello from mock
```

So the test asserts on a known value rather than on whatever a live model happened to say:

```al
Assert.AreEqual('Hello from mock', Result.Output(), 'Unexpected output');
```

Image: `Mock.SetNextImageBase64(...)` then `Client.GenerateImage(Mock.ImageModel(...), ...)`.

For tool-loop tests, `SetNextToolCallThenResponse` queues a tool call first and the final response on the next turn. The tool-call turn has no final response text unless you use its overload with explicit tool-turn text.

Full factory surface: [Mock provider](/docs/providers/mock). Contribution rule: mock-provider tests cover provider or client logic you touch. See [Contributing](https://github.com/GuillemPM/AL-AI-Toolkit/blob/main/CONTRIBUTING.md).
