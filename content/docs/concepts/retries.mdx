title: Retries

A provider can throttle or time out even when your request is correct. The client retries those temporary failures before it raises an error, so a single slow response does not break the page or job.

## Set the retry budget

Set the number of extra attempts on the request:

```al
Request.SetMaxRetries(1);
Result := Client.GenerateText(Model, Request);
```

| Setting | Attempts |
|---|---|
| Not set | Up to 3 (the default of 2 retries) |
| `SetMaxRetries(0)` | 1, no retries |
| `SetMaxRetries(N)` | Up to N + 1 |

The short overloads, such as `GenerateText(Model, Prompt)`, use the default. `GetMaxRetries` returns the value that applies, and `ClearMaxRetries` restores the default.

Between attempts the client waits a short, growing delay (a fraction of a second, at most two seconds). The time limit from `SetTimeout` applies to each attempt, not to the whole call.

## What is retried

| Error type | Retried |
|---|---|
| `RateLimited` | Yes |
| `Timeout` | Yes |
| `ProviderUnavailable` | Yes |
| Every other type | No, the error is raised at once |

An authentication or invalid-request error will not succeed on a second try, so the client does not spend attempts on it. See [Error handling](/docs/concepts/errors) for the full list.

## Choose a value

| Where the call runs | Suggestion |
|---|---|
| Interactive page, user is waiting | `0` or `1`, then show a soft-fail message |
| Job queue or background task | Default, or higher when the provider throttles often |
| Tool loop with several steps | Default. Each step has its own retry budget |

Every attempt is a separate model call, so retries count toward `GetStepCount()` and the token totals on the result.

## Image requests

`"AIOS Image Request"` has the same `SetMaxRetries` and `GetMaxRetries` procedures, with the same default and the same retried error types.
